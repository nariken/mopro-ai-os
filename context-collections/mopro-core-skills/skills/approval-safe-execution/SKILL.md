# Approval-safe execution

外部状態を変える作業では、準備と実行を分離する。依頼の完了に必要な範囲だけを変更する。

## 実行前

- 対象、変更内容、宛先、公開範囲、費用、取消可能性を特定する。
- 下書き、プレビュー、シミュレーションが可能なら先に作る。
- 認証情報やAPIキーを探したり、未許可のAPIを代替手段として使ったりしない。
- 承認は具体的な実行単位に対応させる。以前の一般的な承認を別の送信や課金へ流用しない。

## 実行

- 同じ操作の重複実行を防ぐ。結果が不明な場合は再実行前に状態を確認する。
- 予定外の対象、費用、権限要求が現れたら停止する。
- 部分成功では、成功済みと未実行を分けて記録する。

## 実行後

変更結果、対象、日時、確認方法を簡潔に報告する。公開URL、処理ID、計測イベントなど検証可能な証跡があれば残す。
