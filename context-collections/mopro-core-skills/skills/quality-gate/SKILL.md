# Quality gate

「作った」と「使える」を分ける。成果物の種類に合った少数の重要条件で判定する。

## 受入条件

- 目的に対する機能と対象範囲が満たされている。
- 重要な事実、計算、リンク、入出力が確認できる。
- 失敗時の挙動と、利用者が次に取る行動が明確である。
- 権限、費用、個人情報、公開範囲が依頼の境界内である。
- 日々の一人運用で再実行でき、手順や証跡が残る。

## 検証

可能なら代表的な正常系、境界条件、失敗系を実行する。文面の存在だけを確認するテストではなく、観測可能な結果を確認する。実環境で実行できない項目は未検証として残し、検証済みに見せない。

## 完了報告

`合格`、`条件付き合格`、`未合格` のいずれかを示し、確認した証拠と残課題を簡潔に添える。重大条件が未確認なら完成扱いにしない。
